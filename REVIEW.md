# REVIEW.md

Review of the starter `app/main.py`. Line numbers refer to the original starter file.

Every fix is in the submitted `app/main.py`. The three helper functions were kept but rewritten:
each one needed the record's attendance date and the employee's shift as inputs, which the
originals did not take, so reusing them as they stood was not possible.

## Looked at and decided it was fine

* **`load_dotenv()` before `os.getenv` (L20-23).** Correct precedence: `load_dotenv` does not override variables that are already set, so the grader's injected `MONGO_URI` / `MONGO_DB` win over any local `.env`. I kept it and only replaced `os.getenv(k, default)` with `os.getenv(k) or default`, so that an empty string does not become a connection string.
* **`IST = timezone(timedelta(hours=5, minutes=30))` (L25).** Right value, and a fixed offset is the right type for IST, which has no DST. Kept as is.
* **One module-level `MongoClient` (L22).** Correct, not a leak: PyMongo's client is thread-safe and owns a connection pool, so sharing one across requests is what you want. Creating one per request would have been the defect.
* **`find(q, {"_id": 0})` in `list_employees` (L95).** Correctly keeps `_id` out of the response; I kept the projection and extended the same treatment to `attendance_logs`.
* **The slice in `list_attendance` (L147)** uses the *correct* `(page - 1) * page_size` offset. It is the inconsistency with `list_employees` (L93) that gives the off-by-one away; only the latter was wrong.
* **`max(0, ...)` in `compute_overtime` (L47).** Genuinely useful: it stops a punch-out before shift end producing negative overtime. The bug next to it was the missing 30-minute floor, not this.
* **`doc.pop("_id", None)` after `insert_one` (L84).** Necessary, because `insert_one` mutates the dict it is given. I now pass a copy instead, which makes the intent explicit, but the original was not wrong.
* **`status_code=201` on the decorator (L77, L99).** The right way to set a non-200 success status in FastAPI.
